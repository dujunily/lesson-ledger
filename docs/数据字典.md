# 数据字典 · 课时簿

版本：schemaVersion = 1（对应 App 1.0.0）
存储：Room（本地 SQLite，`lesson_ledger.db`）+ 坚果云上的 JSON 快照。远端快照与本地表结构一一对应，字段名完全相同。

---

## 0. 全局约定

| 约定 | 说明 |
| --- | --- |
| 主键 | `id`：字符串 UUID，由**客户端生成**（离线也能建记录），不用自增 ID |
| 金额 | `Long`，单位**分**。`480000` = ¥4,800.00。禁止用 Float/Double |
| 课时 | `Long`，单位**半节**（1 节 = 2）。`40` = 20 节。支持「已上 0.5 节」= `1` |
| 日期 | 只有日期的字段用 `String`，格式 `yyyy-MM-dd`（如生日、缴费日、有效期） |
| 时间点 | 需要精确到时刻的用 `Long`，UTC 毫秒时间戳（如上课时间、创建时间） |
| 时间字符串 | 每天几点上课用 `String`，格式 `HH:mm`（本地时间，配合 `weekdayMask` 判断） |
| 布尔 | `Boolean`，SQLite 存 0/1 |
| 空值 | 可空字段用 `null` 表示「未填/长期有效」，不用空字符串代替 |

### 0.1 四件套（所有同步表都有）

| 字段 | 类型 | 含义 | 取值范围 / 约束 |
| --- | --- | --- | --- |
| `id` | String | 记录唯一标识 | UUID v4；创建后不变 |
| `createdAt` | Long | 创建时间（UTC 毫秒） | > 0；合并时用于稳定排序 |
| `updatedAt` | Long | 最后修改时间（UTC 毫秒） | > 0；**每次用户可见的修改都要更新**；冲突判定与增量上传都依赖它 |
| `deleted` | Boolean | 软删除标记（墓碑） | `true` 表示已删除但记录仍保留，用于把删除同步给其它设备 |

> 系统派生字段（`courses.totalLessonsBoughtHalf`、`lessons.paymentId`）由程序重算写入，**不会**改动 `updatedAt`，否则会造成「永远在上传」。

## 2. courses（课程 / 培训班）

| 字段 | 类型 | 可空 | 含义 | 取值 / 备注 |
| --- | --- | --- | --- | --- |
| `id` | String | 否 | 主键 | UUID |
| `childId` | String | 否 | 所属孩子 | 外键 → `children.id`；逻辑删除孩子时级联软删其课程 |
| `orgName` | String | 否 | 机构 / 培训班名称 | 「星海钢琴艺术中心」 |
| `courseName` | String | 否 | 课程名 | 「钢琴一对一」；同名课程允许存在（按 ID 区分） |
| `category` | String | 否 | 科目 | `MUSIC/SPORTS/ACADEMIC/ART/DANCE/CODING/OTHER`，默认 `OTHER` |
| `teacher` | String | 是 | 老师 | |
| `location` | String | 是 | 上课地点 | |
| `weekdayMask` | Int | 否 | 每周上课日位掩码 | bit0=周一 … bit6=周日；`0` 表示没排课。例：周三=`8`，周六=`32`，周三+周六=`40` |
| `startTime` | String | 是 | 上课时间 | `HH:mm`；为空则不自动生成课表 |
| `durationMinutes` | Int | 否 | 单次时长（分钟） | 默认 60 |
| `warningThreshold` | Int | 否 | 剩余课时提醒阈值（节） | 1–99，默认取设置里的默认阈值（5） |
| `remindBeforeMinutes` | Int | 否 | **上课前多少分钟发通知提醒** | 0–240，`0` = 不提醒；默认 30（取设置里的默认值）。v1→v2 新增 |
| `status` | String | 否 | 状态 | `ACTIVE 在读` / `PAUSED 暂停` / `FINISHED 已结束` / `REFUNDED 已退费` |
| `totalLessonsBoughtHalf` | Long | 否 | 购买课时合计（半节） | **冗余只读**，由缴费记录汇总，仅用于显示「总计 N 节」 |
| `note` | String | 否 | 备注 | |
| `createdAt` / `updatedAt` / `deleted` | | | 见 0.1 | |

约束与规则：

- `status != ACTIVE` 的课程不生成提醒、不自动生成课表；
- `remindBeforeMinutes > 0` 且课程为 ACTIVE 时，其「待上」课次会排一个 AlarmManager 精确闹钟，触发时刻 = `scheduledAt − remindBeforeMinutes × 60000`；
- 改了课程的 `startTime` / `weekdayMask` 后，**今天及以后还没上的自动课次**会跟着更新（时间同步、取消的星期几作废），闹钟随之重排；更早的历史课次不动；
- 已结束/已退费的课程在列表里单独分组；
- 冲突副本的 `courseName` 会加 `[冲突副本] ` 前缀，且 `status` 落为 `PAUSED`。

## 3. payments（缴费 / 退费记录）

| 字段 | 类型 | 可空 | 含义 | 取值 / 备注 |
| --- | --- | --- | --- | --- |
| `id` | String | 否 | 主键 | UUID |
| `courseId` | String | 否 | 所属课程 | 外键 → `courses.id` |
| `payDate` | String | 否 | 缴费日期 | `yyyy-MM-dd`；统计按它归月，FIFO 按它排序 |
| `amount` | Long | 否 | 实付金额（分） | **退费为负数**；允许 0（纯赠送） |
| `originalAmount` | Long | 是 | 原价（分） | 用于显示「原价 ¥5,200」划线对比 |
| `lessonsBoughtHalf` | Long | 否 | 购买课时（半节） | ≥ 0；0 且金额 0 = 纯赠送批次 |
| `lessonsBonusHalf` | Long | 否 | 赠送课时（半节） | ≥ 0；计入可扣课时，但不摊单价 |
| `payMethod` | String | 否 | 支付方式 | `WECHAT/ALIPAY/BANK/CASH/OTHER` |
| `validUntil` | String | 是 | 课时有效期 | `yyyy-MM-dd`；空 = 长期有效 |
| `receiptPaths` | String | 是 | 收据照片 | JSON 数组字符串，元素是本地相对路径 / `attachments/` 下的文件名 |
| `note` | String | 否 | 备注 | 冲突副本在此加前缀 |
| `createdAt` / `updatedAt` / `deleted` | | | 见 0.1 | |

派生规则：

- `totalHalf` = `lessonsBoughtHalf + lessonsBonusHalf`；
- `isRefund` = `amount < 0`；
- FIFO 排序键 = (`payDate` 升序, `createdAt` 升序)；
- 有效单价分母**只算** `lessonsBoughtHalf`，且跳过 `amount == 0`、`lessonsBoughtHalf == 0` 的批次。

## 4. lessons（上课记录）

| 字段 | 类型 | 可空 | 含义 | 取值 / 备注 |
| --- | --- | --- | --- | --- |
| `id` | String | 否 | 主键 | UUID；自动排课生成的是**确定性 UUID**（`UUIDv3("lesson:<courseId>:<yyyy-MM-dd>")`），两台设备算出同一个 id，合并后不会出现重复课次 |
| `courseId` | String | 否 | 所属课程 | 外键 → `courses.id` |
| `scheduledAt` | Long | 否 | 计划上课时间 | UTC 毫秒；日历按本地日期归组 |
| `actualAt` | Long | 是 | 实际打卡时间 | UTC 毫秒；点「已上」时写入 |
| `durationMinutes` | Int | 否 | 本次时长（分钟） | 默认继承课程 |
| `status` | String | 否 | 状态 | `PENDING 待上` / `DONE 已上` / `LEAVE 请假` / `ABSENT 缺勤` / `RESCHEDULED 调课` / `CANCELLED 已取消` |
| `deductedHalf` | Long | 否 | 本节省扣课时（半节） | 0 / 1（半节）/ 2（1 节）；由状态与扣课规则决定 |
| `paymentId` | String | 是 | FIFO 命中的缴费批次 | **只读**，由系统重算：先扣最早的批次 |
| `teacher` | String | 是 | 本次老师 | 可与课程默认老师不同 |
| `note` | String | 否 | 备注 | |
| `autoGenerated` | Boolean | 否 | 是否由课表自动生成 | `true` 的记录由「每周上课日 + 上课时间」批量生成，可自由修改 |
| `suppressed` | Boolean | 否 | 已手动删除的墓碑 | 用户删掉某一节**自动**课次后置 1，`ensureUpcomingLessons()` 重排时跳过这一天，不会把课补回来；手工加课次会清掉墓碑 |
| `createdAt` / `updatedAt` / `deleted` | | | 见 0.1 | |

扣课规则（`deductedHalf` 的取值来源）：

| 状态 | 默认扣课 | 设置项 |
| --- | --- | --- |
| 已上 | 1 节（2） | 固定 |
| 已上（0.5 节） | 半节（1） | 打卡时可选 |
| 请假 | 0（退课时） | 设置里「请假也扣课时」打开后改为 2 |
| 缺勤 | 1 节（2） | 设置里「缺勤也扣课时」关闭后改为 0 |
| 调课 | 0（改期另记） | 固定 |
| 已取消 | 0 | 固定 |
| 待上 | 0 | 固定 |

## 7. 云端文件格式

### 7.1 manifest.json（明文，小文件）

```json
{
  "schemaVersion": 1,
  "lastDeviceId": "b9224db0-...",
  "lastDeviceName": "妈妈的手机",
  "lastWriteAt": 1793172091764,
  "dataEtag": "f209bc2973771c0474df32d6f001706a",
  "recordCount": 15
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schemaVersion` | Int | 数据结构版本；远端更高时本机拒绝写入并提示升级 |
| `lastDeviceId` | String | 最后写入的设备 UUID |
| `lastDeviceName` | String | 最后写入的设备名（设置 → 家庭共享 里可改），用于在对方手机上显示「云端最后由谁写入」 |
| `lastWriteAt` | Long | 最后写入时间（UTC 毫秒） |
| `dataEtag` | String | 数据文件 ETag，用于判断远端是否变化 |
| `recordCount` | Int | 四张表记录总数（含墓碑），用于快速自检 |

### 7.2 data.json / data.enc（全量快照）

```json
{
  "schemaVersion": 1,
  "exportedAt": 1793172091764,
  "deviceId": "b9224db0-...",
  "children": [ ... ],
  "courses": [ ... ],
  "payments": [ ... ],
  "lessons": [ ... ]
}
```

- `data.json`：上面这段 JSON 经 **GZIP** 压缩后的二进制（magic `1F 8B`）；
- `data.enc`：开启备份加密后取代 `data.json`，格式为 `LLB1` + 16B 盐 + 12B IV + AES-256-GCM 密文，明文体是「GZIP 压缩后的 JSON」，密钥 = PBKDF2-HMAC-SHA256(口令, 盐, 120000 次, 32 字节)；
- 切换加密开关时，App 会写入新文件名并删除另一份，避免两台设备各读一份。

### 7.3 目录

```
/课外班管家/
├── manifest.json
├── data.json | data.enc
├── backups/data-yyyyMMdd-HHmmss-SSS.json   最多 10 份，超出的从旧到少删除
└── attachments/<uuid>.jpg                  收据原图（最长边 1600px，JPEG 82）
```

## 8. 派生数据（不落库，实时计算）

### 8.1 课程统计 `CourseStats`

| 字段 | 单位 | 计算方式 |
| --- | --- | --- |
| `purchasedHalf` | 半节 | Σ(`lessonsBoughtHalf + lessonsBonusHalf`)，未删除的缴费 |
| `usedHalf` | 半节 | Σ(`deductedHalf`)，状态为已上/缺勤等实际扣课的记录 |
| `remainingHalf` | 半节 | `purchasedHalf − usedHalf`，可为负（超扣） |
| `paidCents` | 分 | Σ(`amount`)，退费为负，可能得到净额 |
| `unitPriceCents` | 分/节 | Σ(非 0 金额批次的 `amount`) ÷ Σ(非 0 金额批次的 `lessonsBoughtHalf`) × 2，四舍五入；无有效批次时为 0 |
| `pendingValueCents` | 分 | `remainingHalf × paidCents ÷ purchasedHalf`，一次除法四舍五入。**不用**「单价 × 课时」——单价只精确到分，42 节课会算出 ¥3000.06 比实付还多；用原始比例算，结果天然 ≤ `paidCents` |
| `doneCount` | 节 | 状态为已上的记录条数 |
| `overdrawnHalf` | 半节 | `usedHalf − purchasedHalf`（> 0 时表示超扣） |
| `expiringAt` | 日期 | 还有剩余课时且最近的 `validUntil` |
| `nextLessonAt` | 时间 | 未来的最近一条 `PENDING` 上课时间 |
| `batches` | 列表 | FIFO 批次：每批的总课时、已用课时、金额、缴费日 |
| `allocation` | 映射 | 每节课 → 命中的缴费批次；`unattributedHalf` 为无法归属的部分 |

### 8.1.1 排课规则（`ensureUpcomingLessons()`）

自动排课每 14 天重算一次，规则如下：

| 课程状态 | 是否自动生成课次 |
| --- | --- |
| `courses.startTime` 为空（接龙课 / 临时约课） | **不生成** —— 时间不固定，只能手工加课次 |
| `courses.startTime` 有值且 `weekdayMask ≠ 0` | 按「每周上课日 + 上课时间」生成未来两周的 `PENDING` 课次 |
| `lessons.suppressed = 1` 的日期 | **跳过** —— 用户手动删过这一天，不再补回来 |

- 手工加课次复用 `UUIDv3("lesson:<courseId>:<yyyy-MM-dd>")` 这个确定性 id，和自动课次同一天不会重复出现两条；
- 删掉的自动课次会留墓碑（`deleted = 1` + `suppressed = 1`），课程详情页有「已移除的课次 · 点按恢复」入口；
- 课程改了上课时间 → 已生成但还没上的自动课次跟着改时间；取消了某个上课日 → 那天没上的课次作废。

### 8.2 提醒 `Reminder`（按优先级排序，最多 5 条）

| 类型 | 触发条件 | 严重度 |
| --- | --- | --- |
| `OVERDRAWN` 超扣 | 已扣课时 > 购买课时 | 3 |
| `LOW_LESSONS` 课时不足 | 买过课时，且剩余 ≤ 课程阈值 | 剩余 ≤ 0 为 3，否则 2 |
| `EXPIRING` 即将到期 | 有剩余课时，且 0 ≤ 距到期天数 ≤ 30 | 2 |
| `TODAY` 今天有课 | 今天有 `PENDING` 记录 | 1 |
| `WEEK_UNCLOCKED` 本周未打卡 | 本周已过日期上仍有 `PENDING` | 1 |

### 8.3 统计口径

- 支出/退费按 **`payDate`** 归入月份/年份，不按创建时间；
- 净支出 = 支出合计 − 退费合计；
- 科目占比按缴费金额聚合（退费抵减）；
- 机构 Top 5 按机构累计实付金额降序；
- CSV 列：`日期,孩子,机构,课程,金额,课时,备注`，金额保留两位小数（元），课时按节（半节会显示 0.5），含逗号/引号的字段会加引号转义。

## 9. 兼容与升级

- 当前 `schemaVersion = 1`；
- 读到更高的远端 `schemaVersion` 时，App 会停止写入并提示「远端数据版本高于本机」，避免新版字段被旧版覆盖；
- **Room 版本 = 3**：
  - v1 → v2 加了 `courses.remindBeforeMinutes INTEGER NOT NULL DEFAULT 30`，显式 `Migration(1,2)`；
  - v2 → v3 加了 `lessons.suppressed INTEGER NOT NULL DEFAULT 0`，显式 `Migration(2,3)`；
  - 两步都是显式迁移，**不会**清库；
- 已移除 `fallbackToDestructiveMigration()`：账本是钱，结构变更缺 migration 时宁可启动报错（数据在坚果云还有一份可拉回），也不悄悄把本地库删掉；
- `remindBeforeMinutes` 带默认值，老版本 App 读到新字段会忽略，新版本读到老数据用默认值 30，两端都能正常同步。
